# Website / app split

Webklip’s marketing site and clipboard app started as one Bun process. They are being separated so the **app** can be open-sourced while the **website** (SEO landings, legal chrome, marketing home) lives in its own repo later.

## Phase 1 (current layout)

| Path | Role |
|------|------|
| [`website/`](../website/) | Marketing sources: HTML templates, landings, copy docs, [`website/build.ts`](../website/build.ts) |
| [`website/reserved-paths.json`](../website/reserved-paths.json) | First-path segments owned by the website (generated by the website build) |
| [`src/`](../src/), [`assets/`](../assets/) | OSS app: API, SSR clip UI, auth, WebSockets |
| `dist/pages/` | Built marketing HTML + manifests (`routes.json`, `resource-links.json`, `reserved-paths.json`) |

Root scripts:

- `bun run build:static` → `website/build.ts` → `dist/pages/`
- `bun run build` → assets + static
- Dev watches `website/` and rebuilds pages on change

The app still **serves** `dist/pages` via [`src/routes/static.ts`](../src/routes/static.ts) (website first, then product routes). When `/` is not in the marketing manifest, [`AppHome`](../src/views/AppHome.tsx) handles it (create clip + login/register). With the website built, marketing wins and that route is unused.

Production Docker copies `dist/` and `website/reserved-paths.json` only — not the full website source tree.

Runtime coupling that still goes through the app:

- Homepage `<!--EXPLORE_PREVIEW-->` filled from public clips
- `/sitemap.xml` merges static paths + public clip URLs
- Footer resource links read `dist/pages/resource-links.json` (fallback: `website/static/landing-pages.json`)
- Reserved slug checks merge app routes + marketing list ([`src/lib/reserved-paths.ts`](../src/lib/reserved-paths.ts))

## Reserved paths

**App-owned** (always reserved in code): `account`, `api`, `app`, `new`, `login`, `klipwall`, …

**Website-owned** (from JSON): `about`, `privacy`, `docs`, SEO landings (`online-clipboard`, …).

Load order for the marketing list:

1. `MARKETING_RESERVED_PATHS` env (file path)
2. `dist/pages/reserved-paths.json`
3. `website/reserved-paths.json`

After the website leaves this repo, keep shipping a copy of that JSON with the app deploy (or set the env) so clips cannot collide with production marketing URLs.

## Phase 2 (later — separate repos)

1. Move `website/` to its own repository and host it as static files (CDN / nginx).
2. Put a **reverse proxy** (or CDN rules) in front of `webklip.com`:
   - Paths in the website route manifest → website origin
   - Everything else (`/api/*`, `/ws/*`, `/assets/*`, `/new`, `/account`, `/:slug`, …) → Bun app
3. Stop building/serving marketing pages from the app image.
4. Sync `reserved-paths.json` from the website repo into the app deploy.
5. OSS `/` without marketing pages already uses [`AppHome`](../src/views/AppHome.tsx). Follow-up: keep API `/docs` with the app so self-hosters are not dependent on the marketing repo.
6. Decouple explore preview / sitemap / shared `app.css`+`app.js` landing helpers as needed.

```text
Browser → Edge router
            ├─ path ∈ website manifest → Website (static)
            └─ else                    → App (Bun)
                                         └─ rejects reserved marketing slugs on create
```

Until phase 2, treat `website/` as a folder that can be copied out with minimal path edits; do not add new hard dependencies from `src/` onto `website/static/**` source files.
